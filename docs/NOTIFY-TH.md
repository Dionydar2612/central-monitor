# แจ้งเตือนไป Microsoft Teams

central ส่ง **การ์ด (Adaptive Card)** เข้าช่อง Teams เมื่อสถานะเปลี่ยน
ส่งครั้งเดียวต่อการเปลี่ยน (หลังยืนยันตามเวลาในการ์ด Alerts ปริยาย 3 นาที) ไม่ส่งซ้ำระหว่างที่ยังเป็นอยู่

| ระดับ | ส่งเมื่อ | สีการ์ด |
|---|---|---|
| เครื่อง Down | agent ไม่ส่งข้อมูล / node_exporter ไม่ตอบ | แดง |
| Error | disk / CPU / RAM ถึงเกณฑ์ error, service สำคัญหยุด, ping หาย, bottleneck ระดับ error | แดง |
| Warning | ถึงเกณฑ์ warning | เหลือง |
| กลับมาปกติ | ปัญหาหาย (บอกว่าเป็นนานเท่าไหร่) | เขียว |
| Web / SSL check | เว็บล่ม / ใบรับรองใกล้หมด / กลับมา (ต้องเห็นซ้ำ 2 รอบ) | แดง / เหลือง / เขียว |

**1 การ์ดต่อ 1 เรื่อง** (เครื่องใครเครื่องมัน เรื่องใครเรื่องมัน) การ์ดมีบรรทัดเดียว + เวลา

ตัวอย่าง
```
🔴 ubuntu01 · Disk / เต็ม 93% (เกณฑ์ 90%)
🔴 win2 · เครื่องดับ หรือไม่ส่งข้อมูล
🔴 win3 · Service TermService หยุดทำงาน
🟡 host-window · RAM ใช้ไป 83% (เกณฑ์ 80%)
🟢 lx · CPU กลับปกติ (12%) · เป็นอยู่ 25m
🔴 เว็บ shop ล่ม (HTTP 503)
```

## สรุปสถานะประจำวัน (Daily Summary: Morning / Evening Report)

> **กฎของรายงาน: ห้ามใช้ค่าเฉลี่ย (Average) ทุกกรณี** ไม่เอาค่าของหลายเครื่องมาหารเฉลี่ย
> แสดงค่าของแต่ละเครื่อง + ค่าสูงสุด (พร้อมชื่อเครื่อง) เท่านั้น

ตั้งเวลาเอง เช่น `08:00, 17:00` · ช่วงเวลาของแต่ละรอบ:

| รอบ | ช่วง | แสดง |
|---|---|---|
| 08:00 (Morning Report) | 00:00–08:00 | ค่าปัจจุบันของแต่ละเครื่อง + ค่าสูงสุดในช่วง |
| 17:00 (Evening Report) | 08:00–17:00 | ค่าปัจจุบัน + ค่าสูงสุดในช่วง + เทียบค่าปัจจุบันกับรอบ 08:00 (▲ / ▼) |

(รอบแรกของวันเริ่ม 00:00 · รอบถัดไปเริ่มที่เวลาของรอบก่อน · ก่อน 12:00 = Morning, หลังจากนั้น = Evening)

| ข้อมูล | แสดง |
|---|---|
| UP / DOWN / PAUSE / UNKNOWN | จำนวนเครื่อง (UP ที่มี Warning / Error บอกจำนวนแยก) |
| Incident | จำนวนครั้งในช่วง + รายละเอียด (เวลา, เครื่อง, sensor, ระดับ, ค่าสูงสุด) สูงสุด 15 รายการล่าสุด |
| Downtime | เวลาที่เครื่องดับในช่วง ต่อเครื่อง (ยังดับอยู่ = นับถึงตอนนี้) |
| Recovery | จำนวนเครื่องที่กลับมาทำงาน + เวลา + ดับไปนานเท่าไร |
| ตารางต่อกลุ่ม | Machine · CPU · RAM · Disk (แยกทุกไดรฟ์) · Disk I/O · แต่ละช่อง = ค่าตอนนี้ / สูงสุดในช่วง / เทียบรอบก่อน |
| Group Summary | CPU / Memory / Disk สูงสุดของกลุ่ม (ตอนนี้ และในช่วง) พร้อมชื่อเครื่อง (และไดรฟ์) |

```
📋 Central Monitor Daily Summary · Evening Report 10/11/2026 17:00
ช่วงเวลา 08:00–17:00 · เทียบกับรอบ 08:00
🟢 UP: 3 เครื่อง (มี Warning / Error 2)   🔴 DOWN: 1   ⏸ PAUSE: 1   ❔ UNKNOWN: 0
Incident: 3 ครั้ง · Downtime: PROD-01 12m, win2 25m (ยังดับอยู่) · Recovery: 1 เครื่อง · PROD-01 09:12 (ดับ 12m)

กลุ่ม TQ/PROD · 3 เครื่อง
CPU สูงสุด: 92% (PROD-03) · ช่วง 08:00–17:00: 97% (PROD-03)
Memory สูงสุด: 91% (PROD-03) · ช่วง 08:00–17:00: 93% (PROD-03)
Disk สูงสุด: 88% (PROD-03 C:) · ช่วง 08:00–17:00: 93% (PROD-03 C:)
Machine   | CPU                          | RAM                          | Disk          | Disk I/O
PROD-03   | 92% 🔴 สูงสุด 97% 08:00: 95% ▼3 | 91% 🔴 สูงสุด 93% 08:00: 80% ▲11 | C: 88% (สูงสุด 93%) | -
PROD-01   | 35% สูงสุด 61% 08:00: 30% ▲5    | 62% สูงสุด 70% 08:00: 60% ▲2    | C: 55% ▲1     | 1.4% สูงสุด 30%
```
- ค่าสูงสุดในช่วง = `max_over_time` จาก Prometheus ของเครื่องนั้น (ทุก 1 นาที) · ค่า CPU ของเครื่อง = CPU usage 5m ของเครื่องนั้น
- ค่าที่เกินเกณฑ์มี 🟡 / 🔴 · ปัญหาอื่น (service หยุด, ping ...) แสดงใต้ชื่อเครื่อง
- ค่าที่ใช้เทียบ = รายงานรอบที่ตั้งเวลาไว้ก่อนหน้าในวันเดียวกัน (กด "ส่งสรุปตอนนี้" ไม่เปลี่ยนค่าที่ใช้เทียบ)
- เครื่องเยอะจนการ์ดเกิน ~24KB -> แบ่งส่งหลายการ์ด (ต่อ 2/3 ...)
- ใช้เวลาของเครื่อง central (`TZ` ใน docker-compose ปริยาย Asia/Bangkok)
- ส่งครั้งเดียวต่อเวลาที่ตั้ง (จำไว้ที่ `data/state/notify_summary.json` พร้อมค่าที่ใช้เทียบ) · puller หยุดไปเกิน 15 นาทีหลังเวลานั้น -> ข้าม
- ปุ่ม **ส่งสรุปตอนนี้** ในหน้า Settings = ส่งทันที (ช่วง = ตั้งแต่รอบล่าสุดของวัน)

## ตั้งค่า

1. **สร้าง webhook ใน Teams**
   ช่องที่ต้องการ > `⋯` (More options) > **Workflows** > เลือกเทมเพลต **Send webhook alerts to a channel**
   > ตั้งชื่อ (เช่น Central Monitor) > เลือกทีม/ช่อง > **Add workflow** > คัดลอก URL ที่ได้
   (ถ้าองค์กรยังเปิด Incoming Webhook แบบเดิม ใช้ URL นั้นก็ได้ รูปแบบข้อความเหมือนกัน)
2. **central**: Settings > **Notifications (Microsoft Teams)**
   - วาง Webhook URL > เลือกระดับที่จะส่ง > ใส่เวลาส่งสรุป (ถ้าต้องการ)
   - กด **Send test card** -> ต้องเห็นการ์ดสีเขียว "ทดสอบการแจ้งเตือน" ในช่อง Teams
   - กด **Save notifications** (puller ใช้ค่าใหม่ภายใน ~30 วินาที)

## ข้อควรรู้

- เครื่อง central ต้องออกอินเทอร์เน็ตไปที่ Microsoft ได้ (HTTPS 443) ทั้ง container `central-api` (ปุ่มทดสอบ) และ `central-puller` (ส่งจริง)
- Webhook URL เป็นความลับ (ใครมี URL ก็โพสต์เข้าช่องได้) เก็บใน `config/puller.yaml` -> `notify.teams.webhook_url` หน้าเว็บแสดงแค่ host + 6 ตัวท้าย และ Activity log ไม่เก็บ URL
- ส่งไม่สำเร็จ -> ลองใหม่ 3 ครั้ง แล้วบันทึกใน System log (หน้า Events) ว่า "ส่งแจ้งเตือนไป Microsoft Teams ไม่สำเร็จ"
- ไม่อยากได้รับเรื่องที่รู้อยู่แล้ว: Acknowledge ในหน้า Events (การ์ดที่ส่งไปแล้วไม่ถูกลบ) หรือ Pause เครื่องนั้น
- ดูการส่ง: `docker logs central-puller | grep NOTIFY`

โค้ด: `start_push_log/puller/notify.py` (ส่งจริง) · `web_dashboard/backend/notify_service.py` (ตั้งค่า / ทดสอบ)

## ส่งเฉพาะบางเครื่อง / บางเรื่อง / แต่งข้อความ

ใช้ **Settings > Custom alert rules** (ด้านล่าง) · การ์ด Notifications เหลือแค่ช่อง Teams หลัก, เปิด/ปิด, ระดับที่ส่ง (ส่งเมื่อ) ของ sensor ในตัว และเวลาสรุปรายวัน

## กฎแจ้งเตือนที่สร้างเอง (Settings > Custom alert rules)

| ช่อง | ความหมาย |
|---|---|
| ค่าที่ดู | CPU %, RAM ใช้ไป %, RAM ว่าง %, Disk ใช้ไป % / ว่าง GB / latency (ต่อไดรฟ์), Disk I/O %, CPU queue, Network %, TCP retransmit %, Ping loss / latency, Service หยุด (Windows), **PromQL เอง** |
| โปรแกรม (Windows) | **โปรแกรมไม่ทำงาน** / **CPU % ของโปรแกรม** / **RAM ของโปรแกรม MB** · ชื่อโปรแกรมตามแท็บ Software / Processes เช่น `sqlservr`, `java`, `w3wp` (ไม่ต้องมี .exe, ไม่สนตัวพิมพ์, หลาย process ชื่อเดียวกัน = รวมกัน) |
| พอร์ต / เว็บ | **พอร์ตไม่เปิดรับบนเครื่อง** (Windows: ดูจากรายการพอร์ตที่เครื่องส่งมา ไม่ต้องเปิด firewall) · **พอร์ตเชื่อมต่อจาก central ไม่ได้** (central ต่อ TCP ไปที่ Host ของเครื่อง timeout 5 วิ) · **เว็บของโปรแกรมไม่ตอบ** (central เรียก URL เช่น `http://{host}:8080/health` ผิดปกติ = เรียกไม่ได้ / 10 วิ / HTTP 4xx-5xx) |
| ระดับเมื่อผิดปกติ | กฎแบบ "หยุด / ไม่ตอบ" (service, โปรแกรม, พอร์ต, เว็บ) ไม่มีเกณฑ์ตัวเลข เลือก Error / Warning |
| ไดรฟ์ / mount | เฉพาะค่าของดิสก์ เช่น `D:` หรือ `/var` (ว่าง = ทุกไดรฟ์ แยก sensor ละไดรฟ์) |
| PromQL | ใช้ `$labels` แทนตัวเลือกเครื่อง เช่น `node_load1{$labels}` หรือ `windows_process_working_set_private_bytes{$labels,process="sqlservr"} / 1e9` (หลายค่า -> ใช้ค่าที่แย่ที่สุด) |
| แจ้งเมื่อค่า | ≥ (ค่ามากยิ่งแย่) หรือ ≤ (ค่าน้อยยิ่งแย่ เช่น Disk ว่าง GB) |
| Warning / Error | ใส่อย่างน้อย 1 ค่า |
| ต้องเป็นต่อเนื่องนาน | นาที (แยกจากค่าทั้งระบบในการ์ด Alerts) |
| ใช้กับ | เลือกเครื่อง / กลุ่ม / OS (ไม่เลือก = ทุกเครื่อง) |
| ส่ง Microsoft Teams | ติ๊ก = ส่งการ์ดทั้งตอนมีปัญหาและตอนกลับปกติ **เสมอ** (ไม่ขึ้นกับตัวเลือก "ส่งเมื่อ" ของการ์ด Notifications) |
| ช่อง Teams ของกฎนี้ | webhook URL แยกของกฎ (เช่นส่งเรื่อง DB ไปช่องทีม DB) · ว่าง = ช่องหลัก · ใส่ `-` = ลบ |
| ข้อความบนการ์ด | ของกฎนี้โดยเฉพาะ (ว่าง = แบบทั้งระบบ) |

- ปุ่ม **Preview กับเครื่องตอนนี้** = ดูค่าปัจจุบันและสถานะของทุกเครื่องที่ตรงกฎ ก่อนบันทึก
- ปุ่ม **ทดสอบส่ง Teams** = ส่งการ์ดตัวอย่างของกฎนี้ (ข้อความของกฎ) ไปช่องของกฎ / ช่องหลัก
- ตาราง: คอลัมน์ Teams บอกว่าจะส่งไป "ช่องของกฎ" / "ช่องหลัก" / "ยังไม่ตั้งช่อง"
- ผลของกฎเป็น sensor ชนิด "custom" ในหน้า Events (Acknowledge / ประวัติปัญหา / สรุปรายวันได้เหมือน sensor ปกติ)
- เก็บใน `config/puller.yaml` -> `alert_rules:` · ตัวตรวจ `start_push_log/puller/custom_rules.py`

## หน้า Apps & Web (`/apps` · ลิงก์บนหัวหน้า Dashboard)

ดูง่ายๆ ว่าโปรแกรม / เว็บ / พอร์ต / Service ที่สำคัญยังทำงานไหม
- บนสุด: "ทำงานปกติทั้งหมด N รายการ" (เขียว) หรือ "มีปัญหา N จาก M รายการ" (แดง / เหลือง) + ชื่อที่มีปัญหา
- การ์ดละรายการ: จุดสี · ชื่อ · เครื่อง · ข้อความล่าสุด · "ทำงาน 3d" / "หยุด 12m" (มีปัญหาขึ้นก่อน) · คลิก = ไปหน้าเครื่อง
- ตัวกรอง: ทั้งหมด / มีปัญหา / โปรแกรม / Service / เว็บ / พอร์ต + ค้นหา · อัปเดตเองทุก 30 วินาที
- admin: **+ เพิ่ม** เลือกประเภท + เครื่อง + ชื่อโปรแกรม / URL / พอร์ต / service (มีรายการโปรแกรมและพอร์ตที่ทำงานอยู่บนเครื่องให้เลือก)
  -> สร้าง Custom alert rule ให้ (Error, ต่อเนื่อง 2 นาที, ส่ง Teams ช่องหลัก) แก้รายละเอียดต่อได้ใน Settings > Custom alert rules · **× ลบ** = ลบกฎ
- แท็บ Software ของเครื่องมีการ์ด "Watched apps & web" ของเครื่องนั้นด้วย

## ติดตั้ง / ถอน / อัปเดตโปรแกรม (Windows)

เครื่อง Windows ส่งรายการโปรแกรมที่ติดตั้งทุก 15 นาที · central เทียบกับรายการเดิมทุก 5 นาที
- เปลี่ยน -> บันทึกใน System log + แท็บ Software ของเครื่อง (ประวัติ 200 รายการ) + การ์ด Teams 1 ใบต่อเครื่อง
  (เลือก "ติดตั้ง / ถอน / อัปเดตโปรแกรม" ใน "ส่งเมื่อ" ของการ์ด Notifications · ถ้าเคยบันทึกการ์ดนี้ไว้แล้วต้องติ๊กเพิ่ม)
- ครั้งแรกที่เห็นเครื่อง = จำรายการไว้ ไม่แจ้ง · รายการหายเกินครึ่งในรอบเดียว = ถือว่าอ่านไม่ครบ ไม่แจ้งถอน
- เก็บใน `data/state/software.json` · ตัวตรวจ `start_push_log/puller/software_watch.py`
